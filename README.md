# «Акчам кайда?» — аудитор мобильных расходов, ТЗ 4, Осенний хакатон INAI 2026

[![ci](https://github.com/KUMA-ORIGINAL/inai-billing-check/actions/workflows/ci.yml/badge.svg)](https://github.com/KUMA-ORIGINAL/inai-billing-check/actions/workflows/ci.yml)

«Акчам кайда?» (кырг. «Где мои деньги?») читает детализацию за месяц и отвечает на три вопроса:
куда ушли деньги, сколько из них под вопросом и что сделать, чтобы их вернуть. Ядро — обязательная
часть ТЗ 4. Вокруг него — продукт для абонента, его семьи и оператора:

- **Абонент:** находки пяти типов с уликой из детализации, пояснением на русском и кыргызском и готовой претензией.
- **Семья:** один взрослый видит номера родителей и детей, светофор риска и ленту событий.
- **Оператор:** радар коротких номеров по всем абонентам — 7575 списывает у 5 из 5, 8899 только ночью.
- **Telegram:** переслали боту файл детализации — в ответ сводка, «к возврату N сом» и претензия файлом.
- **Тариф (объединили с ТЗ 2):** тот же месяц на пакетном тарифе. Семья может вернуть 204 сом, но на подходящих тарифах платила бы на **2 680 сом меньше каждый месяц**.

**Все 4 обязательных пункта ТЗ и 3 из 3 бонусов** (график, ИИ, PDF) — таблица ниже.
На открытых данных организаторов: **5 из 5 отчётов совпали с эталонами, найдено 20 из 20 аномалий, 0 ложных.**

## Для жюри: запуск одной командой

Нужен только Python 3.10+. Ничего ставить не нужно и интернет не нужен: всё на стандартной библиотеке.

```bash
run.bat data\billing_03.csv          # Windows
./run.sh data/billing_03.csv         # Linux / macOS
python analyze.py data/billing_03.csv   # то же самое без скрипта
```

Результат — в `out/`: **`anomalies.json`** (список `{datetime, type, reason, …}`), `report.json`
(ровно формат `billing_XX_expected.json`), `dropped_rows.csv`, `report.html` и `report.md`.
Без аргументов считаются все пять файлов из `data/`, а **`out/index.html` — приложение «Акчам кайда?»**,
которое открывается без сервера и без интернета (данные семьи вшиты в страницу).
Из Python — как в ТЗ: `import analyze; analyze.analyze("billing.csv")` пишет те же файлы в `out/` и возвращает отчёт.

Сверить с эталоном по правилам автопроверки (не меньше 80% найдено, не больше 2 ложных) и заодно поля отчёта:

```bash
python check.py out/anomalies.json data/billing_03_expected.json
```

```
ЗАЧЁТ: найдено 5 из 5 (100%), ложных: 0 (допустимо не больше 2)
Отчёт:
  valid_rows: совпадает
  …
```

Все пять файлов разом — одна команда (её же запускает CI на каждый push):

```bash
python analyze.py --validate data
```

```
billing_01.csv: поля отчёта совпали — да; аномалий найдено 4 из 4; ложных 0 → ЗАЧЁТ
…
ИТОГО 5/5 ЗАЧЁТ (аномалий 20 из 20, ложных 0)
```

Код возврата `0` — все в зачёте, `1` — хотя бы один файл не прошёл.

**Приложение с сервером** (свои файлы, пороги, «добавить дубль вживую», ИИ-пояснения): `run.bat --serve` →
http://127.0.0.1:8000. Сервер слушает только этот компьютер. Прежний интерфейс — на http://127.0.0.1:8000/classic.

### Приложение рассказывает о себе само

- При первом открытии — приветствие: что это и как работает, в трёх пунктах.
- «Показать за минуту» — экскурсия с подсветкой по всем экранам (11 шагов: сумма, чек-улики, семья, находка, претензия, тариф, сверка с эталоном, радар, режим для родителей, загрузка). Стрелки ← → на клавиатуре, Esc — выход.
- «Автопоказ» внутри экскурсии сам листает шаги каждые 7 секунд — для стенда или проектора.
- Кнопка «?» в шапке открывает приветствие снова.
- Ссылки для показа: `/?tour=1` — сразу экскурсия, `/?autoplay=1` — экскурсия с автопоказом, `/?intro=0` — без приветствия. Работают и на GitHub Pages.

## Telegram-бот

Переслали боту детализацию (CSV, до 5 МБ) — в ответ сводка на русском: сколько потрачено, **«к возврату N сом»**,
главные находки (тип, дата, номер, сумма), экономия на тарифе — и готовая претензия оператору файлом `.txt`.
`/start` — приветствие на русском и кыргызском и подсказка, где скачать детализацию. Не CSV, битый файл
или больше 5 МБ — понятное сообщение вместо ошибки. PDF тоже принимается, если стоит `pdfplumber`.

1. В Telegram откройте **@BotFather** → `/newbot` → имя и логин бота → скопируйте токен.
2. Запустите (компьютер должен быть в интернете; входящие порты не нужны — бот сам опрашивает Telegram):

```powershell
$env:TELEGRAM_BOT_TOKEN = "123456:ABC..."            # токен от @BotFather
$env:APP_URL = "https://kuma-original.github.io/inai-billing-check/"   # необязательно: ссылка в ответе
python analyze.py --bot                               # Linux/macOS: export TELEGRAM_BOT_TOKEN=…
```

Без токена бот сразу выходит с кодом `2` и подсказкой. Токен не печатается ни в консоль, ни в логи.
Считает то же ядро, что и CLI; файл разбирается во временной папке и не сохраняется. Код — `billcheck/bot.py`,
сетевой слой подменяемый: тесты (`tests/test_bot.py`) гоняют бота без сети.

Сервер берёт порт из `PORT`, адрес — из `--host` или `HOST` (по умолчанию `127.0.0.1`, на хостинге `0.0.0.0`).
Загруженные файлы не сохраняются: разбираются во временной папке и удаляются после ответа.

## Правила (по уточнениям организаторов, `CLARIFICATIONS_RU.md`, раздел 4)

| Правило | Реализация |
|---|---|
| Отброшенная строка | по порядку: `empty_line` → `column_count` → `unknown_type` → `bad_datetime` → `bad_number`; заголовок не считается; пустой `number` допустим; каждая физическая строка разбирается отдельно, так что незакрытая кавычка не «съедает» следующие строки |
| Даты | только `YYYY-MM-DD HH:MM:SS` и `DD.MM.YYYY HH:MM:SS`; `2026-09-31` — битая |
| Деньги | `Decimal`, в JSON — 2 знака с `ROUND_HALF_UP`; дубли из отчёта не вычитаются |
| `day_spike` | день против 7 предыдущих полных дней (нулевые дни считаются), population std, первые 7 дней месяца не проверяются, `std = 0` и рост → `z = +inf`; переплата = день − среднее. Ряд — дни основного месяца детализации с 1-го числа, поэтому случайная строка из другого месяца не даёт ложных всплесков |
| `night_charge` | `sms` / `content`, цена > 0, время в `[00:00, 06:00)`; переплата = вся сумма |
| `new_subscription` | первая **в файле** (по порядку строк, как в уточнениях) подписка на номер из 3–6 цифр; повторное списание той же подписки — не новая |
| `duplicate_charge` | совпадают `type, number, duration_sec, mb, cost_som`, разница 0–60 с; флаг на позднюю запись; поиск по времени, а не по порядку строк |
| `international_rate` | номер с `+`, но не `+996`; `996…` — местный; цена минуты > 20; переплата = `max(0, cost − 20·sec/60)` |
| «Возможно лишнее» | сумма аномалий без `day_spike`, одна строка — один раз (`day_spike` агрегирует те же списания) |

## Продукт

- **Для кого:** молодые люди, которые помогают со связью родителям и бабушкам. Пожилые не читают детализацию и случайно подписываются на платный контент.
- **Как это работает в жизни:** скачали детализацию в личном кабинете («Расходы» → «Детализация»), перетащили файл — сразу видно «Можно вернуть 65 сом» и список спорных списаний с объяснением и советом оператора.
- **Заявление:** отметили, что оспорить, — готовый текст в INAI Mobile с датами, номерами и строками детализации. Скопировать, отправить с телефона, скачать или распечатать.
- **Детализация:** обычный список с фильтрами (спорные, звонки, SMS, интернет, подписки) и поиском по номеру; клик по дню на графике открывает его списания.
- **Тариф:** тот же месяц на каждом из 5 тарифов учебного INAI Mobile с 0–2 доппакетами (`data/tariffs.json`, `data/addons.json` из ТЗ 2). Правила как в ТЗ 2: каждый звонок округляется вверх до минуты, 1 ГБ = 1024 МБ, ночной безлимит снимает только ночной интернет [01:00, 07:00), смену советуем, только если экономия за 3 месяца больше 50 сом. Международные звонки, подписки и платный контент в сравнение не входят. На открытых данных экономия от 320 до 906 сом в месяц у каждого, у семьи — 2 679,50 сом в месяц. В `anomalies.json` и `report.json` советник не попадает: формат для жюри не меняется.
- **Семья:** у кого сколько возможно лишнего, у кого новая подписка, и **номера, которые списывают у всех**: 7575 — у 5 из 5, 7 списаний, 85 сом. Ни одно из пяти правил ТЗ этого не видит. В `anomalies.json` такие наблюдения не попадают, чтобы не давать ложных срабатываний.
- **Радар оператора:** короткие номера из всех детализаций — у скольких абонентов, сколько сом, доля ночных списаний и новых подписок, балл подозрительности и тепловая карта «час × номер». Это эвристика экрана: в `anomalies.json` не попадает.
- **Для родителей:** одна кнопка — светлый крупный режим, только суть: сколько вернуть, что сделать, письмо готово. Переключатель RU/KY в шапке.
- **Для жюри на сцене:** «Добавить дубль вживую» дописывает в CSV копию звонка через 20 секунд и сканирует заново — находка появляется на глазах. Блок «Автопроверка» сверяет каждое поле с эталоном.
- **Честно:** оператор учебный, деньги возвращает оператор после проверки, все числа посчитаны из файла.

| Провайдер | Что задать | Цена |

| Любой OpenAI-совместимый | `LLM_BASE_URL` и `LLM_MODEL` (+ `LLM_API_KEY`): Ollama `http://localhost:11434/v1`, Groq, OpenRouter | Ollama — бесплатно и без интернета |
| Claude | `ANTHROPIC_API_KEY` и `pip install -r requirements-llm.txt` | платно |

```powershell
$env:GEMINI_API_KEY = "ваш-ключ"; .\run.bat data\billing_03.csv --llm
```

Модель получает только посчитанные числа. Письмо отбрасывается, если в нём нет главной суммы, есть
число больше 10, которого нет в расчёте (сумма, номер, дата), обещание вернуть деньги, ссылка или текст
не на русском. Нет ключа или сети — отчёт с шаблонными пояснениями.

## Параметры `analyze.py`

| Параметр | Зачем |
|---|---|
| `файлы или папки` | по умолчанию все `data/billing_*.csv` |
| `--out папка` | куда писать (по умолчанию `out`) |
| `--open` | открыть отчёт в браузере |
| `--serve`, `--port 8000` | веб-демо |
| `--llm` | письмо абоненту от ИИ |
| `--validate [папка]` | сверить все `billing_XX.csv` с `billing_XX_expected.json` (по умолчанию `data`) |
| `--bot` | Telegram-бот (токен в `TELEGRAM_BOT_TOKEN`, ссылка на приложение — `APP_URL`) |
| `--make-pdf CSV PDF` | напечатать детализацию в демо-PDF, например `python analyze.py --make-pdf data/billing_01.csv out/billing_01.pdf` |

Коды возврата: `0` — успех, `1` — `--validate` нашёл файл без зачёта, `2` — нет файла, пустой файл, не CSV
или нет заголовка детализации (для `--bot` — нет токена или Telegram его не принял),
`3` — `run.bat` / `run.sh` не нашли Python 3.10+.

```
check.py                самопроверка по правилам жюри
billcheck/parse.py      грязный CSV → списания и отброшенные строки с причинами

billcheck/explain.py    пояснения, советы FAQ, «возможно лишнее»
billcheck/claim.py      заявление на перерасчёт
billcheck/family.py     семья, репутация коротких номеров, сверка с эталонами
billcheck/rich.py       расширенный отчёт: улики, RU/KY-тексты, сводка, сверка с эталоном, радар
billcheck/app.py        приложение: снимок семьи, загрузка CSV/PDF, Markdown и печатный HTML

billcheck/bot.py        Telegram-бот: файл → сводка и претензия (urllib, long polling)
billcheck/validate.py   сверка папки с эталонами: «ИТОГО 5/5 ЗАЧЁТ»
billcheck/tariffs.py    тот же месяц на тарифах ТЗ 2
billcheck/html.py       данные для классических страниц
billcheck/server.py     приложение и его API на http.server
billcheck/llm.py        письмо от ИИ: Gemini, OpenAI-совместимые, Claude
billcheck/templates/    app.html (приложение), report.html, family.html, upload.html, base.css, base.js
data/                   открытые данные организаторов, faq.json, family.json, демо-PDF billing_03_sample.pdf
.github/workflows/      ci.yml (тесты + --validate на каждый push), pages.yml (GitHub Pages)
docs/                   как всё устроено, сценарий демо, план
tests/                  pytest
```
